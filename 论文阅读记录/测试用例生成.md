## Test vs Mutant: Adversarial LLM Agents for Robust Unit Test Generation

2026.2.10 上海交大 阅读日期2026.3.5

AdverTest对抗式双Agent框架，包含两个智能体

- Agent T：**测试生成器**
- Agent M：**变异生成器**

二者形成对抗循环，M生成变异体，指示未覆盖和测试薄弱区域，T生成针对性测试用例，M继续生成新的变异体

**指标**

- 变异分数（Mutation Score）
- 覆盖率（Coverage Rate）
- 缺陷检测率（Fault Detection Rate）

## TestExplora: Benchmarking LLMs for Proactive Bug Discovery via  Repository-Level Test Generation

2026.2.22 微软 北大 阅读日期2026.3.6

当前LLM自动测试生成研究主要集中在两类任务

- **回归测试**，根据已有代码生成测试并提高coverage，问题是默认代码实现是正确的，可能把潜在bug当作feature固化下来
- **Bug复现**，根据issue或bug report生成复现测试

> 这些任务都是被动的，只有在bug已经被发现时才生成测试

**自动测试生成主要基准统计**

![](插图/测试用例生成/TestExplora_框架.png|scale=65)

**数据构造流程图**

![](插图/测试用例生成/TestExplora_数据构造流程.png|scale=65)

**两种测试环境**

- **黑盒测试**，输入包括
  - 文档
  - 函数签名
- **白盒测试**，输入包括
  - 文档
  - 函数签名和函数实现
  - 依赖

**评估指标**

- Head Pass Rate（HP）：测试在修复后代码上通过的比例。
- Fail-to-Pass（F2P）：在旧版本上失败，在新版本上通过
- Entry Coverage（EC)：测试接口的行覆盖率
- Change-focused Coverage（CFG）：被修改代码的行覆盖率

## Learning to Generate Unit Test via Adversarial Reinforcement Learning

2026.9.30 韩国科技院 阅读日期2026.3.8

对抗式测试用例生成，包含两个生成器

- **单元测试生成器**：学习生成测试用例，发现代码生成器的弱点
- **代码生成器**：学习生成能够通过越来越困难测试的代码

使用**强化学习算法GRPO**

- **单元测试生成器奖励**
  - **判别奖励**，评估生成测试是否能区分真实代码与LLM生成代码
  - **有效性奖励**，生成有效测试的比例
  - **最终奖励**，上面两个奖励加权求和
- **代码生成器奖励**，生成代码通过有效测试的比例

**奖励示意图**

![](插图/测试用例生成/UTRL_奖励.png|scale=50)

**循环迭代式训练**

> 先训练单元测试生成器，再训练代码生成器，然后循环直到收敛

**实验设置**

- **训练集**是TACO，15249个指令-代码对
- **评估集**是TACO的945个和LiveCodeBench-v2的511个
- **评估指标**
  - **Best-of-N提升**，先生成N个候选代码，使用生成的测试用例评估，选择通过测试用例最多的代码，然后计算Code Score和CodeAccuracy
  - **单元测试一致性**，先生成N个候选代码，然后在生成的单元测试和GT测试上运行，得到两个Code Score向量，计算Spearman相关系数
